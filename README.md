# dsh-unlag（解除卡顿）

一个按钮，把「改完插件要重启才生效」变成点一下，顺便治好用久了的卡顿。

窗口右上角那个按钮只做两件事：把改过的插件代码原地换掉、把界面重建一次。全程不重启进程，所以会话、正在跑的轮次、排队的消息、没发出的输入都还在。

## 为什么有用

- 开发插件：改完 `.js` 点一下就生效，不用重启 App，也不用刷新页面。
- 装新插件：装完点一下让它进来，接着用。
- 界面用久了发卡：点一下重建，滚动位置和草稿都保留。

以前这三种都得重启 App，现在都不用。有会话正在跑的时候也能点：**马上换，不等空闲**——轮次不会被打断；某一步正好调到被换掉的插件时会报错重来，会话继续。

## 装

```sh
dsh plugin install dsh-unlag
```

装完重载一次 App 让它进来，之后所有更新都走按钮。

## 用

点右上角按钮即可。设置里两行决定它做什么：

- **按下刷新时换掉插件代码**（默认开）
- **按下刷新时重建界面**（默认开）

都开＝先换代码再重建；只开一个＝另一项完全不动（只换代码时页面不刷新，渲染状态和滚动位置全保留）；都不开＝点击无反应。

## 不会丢什么

- 轮次、子代理、终端进程：在宿主侧，不受影响。
- 排队消息、引导队列、输入草稿和附件：重建前会先提交焦点里的内容。
- 有未保存改动或还开着弹窗时：重建被拦下并提示，不硬刷。
- 它自己从不重启或退出 App；缺启动模块时宁可放弃重建并提示，也不冒把 App 带下去的风险。

## 管不到的地方

独立进程和进程级的东西：宠物窗口自己的配置、DSH 自身升级、原生依赖变化。

## 排错

- 日志：`~/.dsh/unlag-reload.log`，每次换代码／跳过／被拦各一行含原因。
- 状态：`GET /dsh-unlag/state` → `{"plugins":true,"page":true}` 是两个开关的当前值。

## 测试

```sh
node test/button.test.mjs   # 开关、接口、忙时立刻换、无宿主不崩
node test/safety.test.mjs   # 崩坏路径与未处理拒绝
```
